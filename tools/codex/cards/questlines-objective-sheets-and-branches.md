`src/systems/questlines/qlSheets.js` loads per-guild objective sheets and evaluates them through `src/systems/questlines/qlLaw.js` and `src/systems/questlines/qlLayer.js`, while `src/ui/questLens.js` surfaces active objectives on the HUD.

## Bindings, One-Way Latches, and Fallback Outcomes

Sheet conditions use the fifteen `BINDING_KINDS` (`started`, `ended`, `success`, `task`, `item`, `clock`, `clockDone`, `step`, `global`, `foeDead`, `act`, `choice`, `all`, `any`, and `not`). Every binding except `act` and `choice` inspects existing quest-machine state such as task latches, timers, and `foeDead` counters.

On each observation pass, `observe()` latches objective states (`opened`, `done`, or `failed`), branch choices, and the resolved outcome onto `quest.ql`. Latches are monotonic and never unlatch, except when `st.reread` performs a one-time reset to mend an older save. If a quest ends without matching a specific outcome rule, `fallbackOutcome` selects the sheet's `success` entry (or `done`) on completion, and `failed` (or the first failure outcome) on failure. Localization keys generated by `sheetTextKey` follow `QUEST.o|r|b.id[.choice]`.

## Text Patches and Shared Branch Prompts

`applyTextPatches` (`src/systems/quest/questPatches.js`) and `src/systems/questlines/qlPatches.js` inject hand-in text patches using message IDs reserved in `QL_MESSAGE_BASE = 1900..1999`. Custom branch prompts in `src/systems/questlines/qlActions.js` re-prompt after `ASK_AGAIN_TICKS = 300` (`30` s at `TICKS_PER_SECOND = 10`) if closed without a decision. In shared party quests (`src/systems/quest/questShare.js`), only the sharer is prompted while `sharerHere` holds, and `receiveSharedQuest` keys the ask latch by task and action index so resynced member copies mirror the choice without re-asking.
